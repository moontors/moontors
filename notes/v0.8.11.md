Moontors 0.8.11

Moontors, the agentic development environment (ADE) for Claude Code, Codex, Gemini CLI, Grok Build and OpenCode, now runs Claude Code 2.1.326 and Grok Build 1.0.88, beside Codex 0.169.0, Gemini CLI 0.68.0 and OpenCode 2.3.0. This release lets an agent read back a session's conversation, such as what a compaction dropped, and lets an MCP server you add take its headers from a command.

What's new:

- **A session's history**: an agent can read back its own session's conversation from Moontors' own record of it, the turns a compaction dropped from its context included, by searching it or paging back from the newest, each answer kept short so it costs little. It can also read another session's, named by its title, though for a session still open it asks that session in a message instead. Its transcript shows the read as a row of its own, with **Open** and that session's title. See [Sessions messaging each other](https://moontors.com/docs/sessions-messaging/).
- **Headers from a command** for MCP servers: a remote server you add for Claude Code or Grok Build can take its headers from a command that runs each time the agent connects, as a sign-in helper that prints a fresh token does. **Check connection** runs it as the agent would, and never shows what it prints. See [Headers from a command](https://moontors.com/docs/configuration/#headers-from-a-command).

What's changed:

- Claude Code 2.1.326 and Grok Build 1.0.88. With Grok Build, `/connectors` opens the MCP servers, as `/mcps` does.
- A folder's trust card names the command a project's MCP server runs for its headers, with Claude Code and Grok Build, and a folder you don't trust runs none. See [A folder's trust](https://moontors.com/docs/configuration/#a-folders-trust).
- A Grok Build plugin of a project whose folder Grok Build doesn't trust shows off, saying why, with **Trust this folder** beside it.
- With Claude Code, a paste that isn't the sign-in code, such as part of it, a web address or a verification code, now says it isn't the code the page shows.

What's fixed:

- With OpenCode and Grok Build, a model, effort or mode the agent changed by itself, as OpenCode does when its catalog reloads, showed as an unrecognized event. The session's settings now follow it, and the agent's echo of a switch made in Moontors shows nothing.

This version updates the Android app; the iPhone app isn't updated this time. The Windows and Linux builds still aren't signed, so Windows asks once before Moontors opens. The README's "First launch" and "Updates" sections say what to expect on each platform.

Found a problem, or have an idea? Open an issue: https://github.com/moontors/moontors/issues/new/choose
