Moontors 0.7.3

Moontors, the agentic development environment (ADE) for Claude Code, Codex and Gemini CLI, now works with projects: add your folders, each with a button in the header that opens its Files, Git and terminals, and start a session in one the way you choose, here, on a new branch or in a new worktree. Settings sets how new sessions start, the board can lay its sections out as columns, and the Git view's left column and colours are new.

What's new:

- **Add project**, in the header, adds a folder as a project, with a button of its own; drag the buttons to put them in your order. A session belongs to the project that holds its folder, its worktrees included. Click a project's name to focus it: Files, Git and Terminal open on its folder with no session needed, each project keeping the view it had open, and its terminals and Files stay with it once its last session goes. See [Projects](https://moontors.com/docs/projects/).
- The part beside a project's name starts a session there. Its menu lists only the ways that can happen now, each saying what it will do and what it leaves as it is: **Here**, **Pull, then here**, **New branch here…**, a new worktree at the default branch, at the current branch or with your uncommitted changes, **New branch in worktree…**, or any of your branches, found as you type, the remote's too. See [Starting a session in a project](https://moontors.com/docs/projects/#starting-a-session-in-a-project).
- **Settings**, in the header (Cmd+, on macOS, Ctrl+, on Windows and Linux), sets each agent's default mode, model and effort for new sessions, the agents' order, and which quick actions the create menu shows, in your order. See [New Session](https://moontors.com/docs/settings/#new-session).
- The board's sections can show as columns side by side, a card wide each, from **Settings › Board**; a card dragged to the board's left edge opens an empty Sessions column there. See [The board](https://moontors.com/docs/sessions-and-board/#the-board).
- Files saves a file as you leave it, as you switch to another file, close its tab or leave Files, on at first and turned off in **Settings › Files**; a save the agent's change refuses keeps your edits. Cmd+S (Ctrl+S on Windows and Linux) saves wherever the focus is in Files. See [Files](https://moontors.com/docs/diff-and-files/#files).
- The Git view's left column shows each section as a pane you size by dragging, every row with an icon of what it is and the branch checked out with a check. Each worktree says how far it's ahead and behind, with a dot for its uncommitted changes, and a branch or a worktree names the sessions working on it, a click opening one. A double-click on a branch checks it out, and **Filter** finds each row by the words it shows. A ref a tool wrote under a remote the repository doesn't have, as a pull request's `pr/25841`, shows among the remote branches. See [Git](https://moontors.com/docs/diff-and-files/#git).
- The Git view's history colours each author and each lane from one palette, the default branch in the app's blue, pinned to the left with its upstream beside it. A commit's labels show where each branch is, on your computer, on a remote or a tag, a branch and its remote branch at one commit as one label. Where there are more lanes than the graph shows, it scrolls sideways, by a trackpad's sideways swipe or Shift and the wheel, and choosing a commit brings its lane into view. Up and Down move through the history as clicks do, and with Shift follow a commit's own lane to its parent. See [Git](https://moontors.com/docs/diff-and-files/#git).
- A commit's details show its signature as a fingerprint, in the warning colour when git finds it bad, expired or revoked, and how many working changes there are, with a button to show them. The working changes always show **Unstaged** and **Staged**, and Shift-click and Cmd-click (Ctrl-click on Windows and Linux) choose several files to stage, unstage or discard at once. The view's columns and panes keep their shares of the window, so another size or display draws them in proportion. See [Git](https://moontors.com/docs/diff-and-files/#git).
- A file's changes open with **Ignore whitespace** and **Wrap lines** on, and turning either off is kept for the folder. See [A file's changes](https://moontors.com/docs/diff-and-files/#a-files-changes).
- **Send** takes files on their own, with nothing typed, on the computer and the phone; a command still needs its words. See [The composer](https://moontors.com/docs/sessions-composer/).
- The Plan view downloads the plan as a Markdown file named for its session, and copies it as Markdown. It keeps its room for the plan, its header saying to answer it in the transcript, where the comments you add in the view go with your answer. See [The Plan view](https://moontors.com/docs/questions-and-plans/#the-plan-view).
- An edit's row marks its changes as Files and Git do, a line only added or removed on its side's tint and every changed word marked. A shell command's question shows the command in the code font with each of its lines, so a script reads as it will run. See [Tools and subagents](https://moontors.com/docs/sessions-tools/) and [Permission modes](https://moontors.com/docs/permission-modes/).
- Codex turns read as they happen, where they had filled with unrecognized events: a pause says **Waiting…**, then **Waited** and for how long; a part Codex's moderation blocked is one note; and its tries at its service again are one note, "The agent lost its connection — reconnecting…", until it goes on. Sessions from before read the same. See [Tools and subagents](https://moontors.com/docs/sessions-tools/) and [What the transcript shows](https://moontors.com/docs/sessions-transcript/#what-the-transcript-shows).
- A command Claude Code runs in its own context, as `/review` does, shows its steps as they happen, in one row with its thinking and tools nested under it. See [Tools and subagents](https://moontors.com/docs/sessions-tools/).
- The agents are updated to Claude Code 2.1.302 and Codex 0.163.0, and Gemini CLI stays at 0.64.0. A forked subagent's row names no model or effort, as Claude Code now runs a fork at the session's own. Codex's **Daybreak** (`/daybreak`) is listed wherever Codex's own terminal lists it, as for a ChatGPT account, with nothing to turn on first, Codex's plugins follow a `[plugins._default]` table in your Codex config, and Codex's new `/config` isn't offered, as Moontors keeps the settings it would change. See [Session settings](https://moontors.com/docs/configuration/#session-settings) and [Plugins](https://moontors.com/docs/configuration/#plugins).
- A running session's pulse uses the graphics processor far less: it changes in small steps while the window is in front, and holds still while it isn't.
- A board card's menu opens from the keyboard on macOS, a turn's footer counts its subagents' edits, a message waiting from several senders shows each one's part, a plugin's MCP server says it comes with its plugin, Create session opens whole rather than filling in as you look, and the window opens the first time at a share of your display, then where you left it.
- Fixed: an agent's command or message holding `$t(` with nothing to close it could freeze the window, or the phone, for minutes (GHSA-5jr9-983r-c8x4, in the i18next library Moontors words its text with); a search stopped at its most matches, or one whose pattern the search refuses, could stop Moontors' background service, and every session with it; archiving a worktree deletes only a branch Moontors made for it, never one you already had (see [Archiving](https://moontors.com/docs/worktrees/#archiving)); a view closed over the board leaves nothing of itself drawn; a file moved right after Files opens is listed in its new place at once; a transcript row's Reply no longer stays shown after a click on the row; and a commit's co-authors each show once.
- Moontors for Android sends files on their own, with nothing typed, with Moontors 0.7.3 on the computer, downloads a plan as a Markdown file through the share sheet and copies it, shows a shell command's question in the code font with each of its lines, and colours a long edit as its colours arrive, so a large change no longer stutters as it opens. It's built on React Native 0.88, through Expo SDK 58. See [Phone](https://moontors.com/docs/phone/).

The macOS and Windows builds still aren't signed, so each asks once before it opens, and macOS updates through its download page for now. The README's "First launch" and "Updates" sections say what to expect on each platform.
