Moontors 0.7.5

Moontors, the agentic development environment (ADE) for Claude Code, Codex and Gemini CLI, now keeps an open row's first line at the top of the transcript while you scroll through it, and its Git view shows the repository's other worktrees in the history. Text fields and the terminal have right-click menus, and every tool reads in words, a command Claude Code describes by what it does.

What's new:

- Scrolling down through an open row in the transcript, its first line stays at the top, on the panel's own colour with the header's line under it, and the rest fades out as it reaches that line, as it does under the header. Once you've scrolled past its end, a row you opened closes, so scrolling back up finds it closed; a row that opens by itself, as an edit's changes do, stays open. Clicking that first line while it's held closes the row and brings the transcript back to its top. See [What the transcript shows](https://moontors.com/docs/sessions-transcript/#what-the-transcript-shows).
- The Git view's history shows the repository's other worktrees, its first column now **Branch / Tag / Worktree**: each worktree at the commit it's at, and one with working changes in a row of its own just above that commit. Choose the row to see those changes, read only, with **Open** for a session working there, or **Start a session here**; a commit's details list each worktree's changes at it too. See [Git](https://moontors.com/docs/diff-and-files/#git).
- Worktrees have a tree for their icon, and the repository's main checkout a home, in the Git view's left column and before where a session works, on its card, in its panel and on the phone. A branch checked out in another worktree pulls there, and offers to check out its commit, detached, or to start a session in that worktree. A stash reads its message, then the branch it was made on. Refs a tool wrote under a remote the repository doesn't have, as a pull request's, are in one **Other refs** folder after the remotes. A file's changes close by an X, **Close the file**. See [Menus](https://moontors.com/docs/diff-and-files/#menus).
- A project's create menu offers **Check out the default branch, then here** where its folder is on another branch, and **Pull the default branch, then here** where the default branch is behind its remote, each named by the branch and greyed, saying where, when another worktree has it checked out. Each item's ↑ and ↓ and its changes read smaller and dimmer than its name. See [Starting a session in a project](https://moontors.com/docs/projects/#starting-a-session-in-a-project).
- A right-click in the composer or any text field opens the system's own menu, with **Cut**, **Copy**, **Paste** and **Select All**; on macOS a misspelled word's spelling suggestions come first, then **Add to Dictionary**. Words you select elsewhere, as in the transcript, offer **Copy**. See [The composer](https://moontors.com/docs/sessions-composer/).
- The terminal has its own menu, from a right-click, the menu key or Shift+F10: **Copy**, **Paste**, **Clear**, which empties the screen and the scrollback but the prompt's line, and **Select All**. See [Its menu](https://moontors.com/docs/terminal/#its-menu).
- Every tool reads in words, on the computer and the phone: an MCP server's tool as `MCP · Moontors · List Sessions`, and another tool's name split into words, as `Tool Search: select:Monitor`; a permission ask names it the same way. A command Claude Code describes is headed by its description, as "Run the unit tests", with the command under **Input**; its permission ask still names the command. See [Tools and subagents](https://moontors.com/docs/sessions-tools/).
- **Action denied**, on a card or in a session's header, is a button: click it, or tap it on the phone, to go to the denied call's row, lit a moment. On a card, the session opens there first. See [A card](https://moontors.com/docs/sessions-and-board/#a-card).
- A message another session sent is a row, as the one that sent it is: "Message from" that session, then the start of the message on a line of its own, which opens to the whole message. Your messages and the agent's replies stand a little apart from the steps around them, on the computer and the phone. See [Sessions messaging each other](https://moontors.com/docs/sessions-messaging/).
- The background tasks over the composer are closed under one heading that counts them, **Background tasks** with how many run, until you open it; each session's stays as you left it while Moontors runs, and `/tasks` opens it. On the phone too. See [Background tasks](https://moontors.com/docs/configuration/#background-tasks).
- **Reply** leaves the focus in the message box, after any words you've typed, on the computer and the phone, and a turn's footer offers no **Reply**. In a question, **Notes** goes while **Other** is chosen, and isn't sent with it. Rephrasing asks for plain text, with no Markdown formatting. A divider marks only a turn a goal or a loop starts by itself. See [Replying to a row](https://moontors.com/docs/sessions-transcript/#replying-to-a-row).
- After a restart, a project you'd focused is focused no more, so Moontors opens on the board with nothing in focus, and a focused session comes back on its transcript with no view open; each view keeps what was in it for when you open it again. Closing a view closes it for every session and project. See [The layout](https://moontors.com/docs/window/#the-layout).
- On a Mac, the header sits right under the strip you drag the window by, with no gap above it.
- Pairing a phone by code works on an IPv6-only network too. See [By code](https://moontors.com/docs/phone/#by-code).
- Fixed: a command Claude Code runs in its own context, as `/code-review`, shows its steps as they happen again, where its row had waited, empty, until it was done.
- Fixed: the Git view's left column fills its height again after it's folded and unfolded.
- Moontors for Android draws its glass's line whole where its corners curve, and a scroll no longer shows what it started on as pressed: a control looks pressed only once a finger stays a moment. Turned on its side with a session open, the app draws its background across the whole screen. Its session header no longer names the model, as the computer's doesn't; the composer's picker does. See [Phone](https://moontors.com/docs/phone/).

The Windows and Linux builds still aren't signed, so Windows asks once before Moontors opens. The README's "First launch" and "Updates" sections say what to expect on each platform.
