Moontors 0.8.5

Moontors, the agentic development environment (ADE) for Claude Code, Codex, Gemini CLI and Grok Build, now runs Claude Code 2.1.321. This release brings what your agents' plugins, hooks and workflows tell you, in the session, with all four agents; a plugin's own notifications; Grok Build's workflows in **Background tasks** and its subagents as rows of their own; MCP servers' forms and links with Grok Build; a session's settings and commands shown at once as you open it; and rows in lists and menus read whole.

What's new:

- What a plugin, a hook or a workflow says for you shows in the session, always under its name, never as Moontors' own words, on your computer and in the phone app. A quiet line in the transcript says who it's from and what they said, a warning, or that they blocked a call, stopped the turn or paused: a Claude Code mod's logged lines; what Gemini CLI's hooks say as they run, a stop one asks for and why one couldn't run; what Grok Build's hooks say, and the hook that blocked a command or stopped the turn, with its reason; a Grok Build workflow's log lines and the message it pauses with; and each line a Grok Build monitor prints, under its description. Under the composer, a Claude Code mod's status line stays until the plugin clears it, a hook's line shows while it runs, Codex's in the words its author set and Grok Build's naming the hook's event, and a mod's toast shows for the time it asked, 30 seconds at most. A question or a permission a plugin's own call asks says which plugin asked. See [What plugins and hooks tell you](https://moontors.com/docs/configuration/#what-plugins-and-hooks-tell-you).
- A Claude Code plugin's mod can notify you itself. Moontors shows it as a notification titled with its session and the plugin it's from, even while you're looking at that session, and your phone gets it too where it gets Moontors' notifications. A plugin can ask for one up to a week ahead, which Moontors holds through a restart, or for one to be dropped if you come back to the session first, and a newer one under the same name replaces the last. One plugin's notifications in a session show 3 at once, then 3 a minute, and your phone gets plugins' notifications 5 at once, then 10 a minute, so Moontors' own always reach it. A notification shows its words as written, never as formatting. See [A plugin's notifications](https://moontors.com/docs/sessions-notifications/#a-plugins-notifications).
- A Grok Build workflow's run shows in **Background tasks** by its name, with what it's for, the phase it's on and how many there are, and the agent working in it, and says "Paused, waiting for you" when its script waits for you. **Output** shows what the workflow has logged, the message it paused with and its result, and **Stop** stops the run as Grok Build's own `/workflow stop` does; while a turn runs, the run stops once the turn ends. On your computer and in the phone app. See [Background tasks](https://moontors.com/docs/configuration/#background-tasks).
- Grok Build's subagents, the ones its model, a `/goal` or a workflow starts, each show as a row of their own, titled by what each was given to do, with their own replies, thinking and tools inside, never in the agent's own reply. A Gemini CLI subagent shows as the row of the call that hands it the work, where it showed as thinking. Grok Build's own questions, where it asks them, come on the question card, as Claude Code's do. On your computer and in the phone app. See [Tools and subagents](https://moontors.com/docs/sessions-tools/).
- With Grok Build, an MCP server's forms and links come to you as cards, as with Claude Code and Codex, and with Codex, a server's OpenAI forms show as forms too. See [Forms](https://moontors.com/docs/questions-and-plans/#forms).
- With Claude Code 2.1.321, where Claude Code has both an auth token and an API key, as your organization's own settings can give it, a session says so once as it starts, naming where each comes from. A skill or command whose name Claude Code won't offer, such as one with a hidden character or two spaces in a row, isn't listed. See [Ways to sign in](https://moontors.com/docs/sign-in/#ways-to-sign-in) and [The commands list](https://moontors.com/docs/conversation-commands/#the-commands-list).
- Opening a session shows its settings, such as the output style, and its `/` list's commands at once, as Moontors last knew them, the newest taking their place if they changed, on your computer and in the phone app. On your computer, a message the folder can't take, such as `/review` outside a git repository, is held as soon as you open a session in a folder Moontors has looked at before. See [The composer](https://moontors.com/docs/sessions-composer/).
- Claude Code's **Style** lists every output style Claude Code runs: each plugin's you have on, named after the plugin, and the project's `.claude/output-styles` in the folders Claude Code reads, as well as Claude Code's own and yours. Its **Default** says it's the default by its own name, where it read "Default (default)". See [Session settings](https://moontors.com/docs/configuration/#session-settings).
- With Claude Code, Moontors lists the project's commands, skills, agents and `CLAUDE.md` files that Claude Code itself reads: commands and skills from the `.claude` folder of the session's folder and of each folder above it, up to the top of its git repository, and in a worktree with none of its own, your main checkout's, tracked or not; `CLAUDE.md` files from the session's folder and every folder above it, as Claude Code reads them. See [The commands list](https://moontors.com/docs/conversation-commands/#the-commands-list).
- A skill's or command's description reads as its agent reads it, so quotes written with a backslash in its file show as plain quotes.
- A row you choose from in a menu or a list shows all of its words, wrapping onto more lines where it's narrow, and so does the line under a row that says why it can't be chosen, such as `/clear`'s in the `/` list. **Earlier plans** lists each plan by its whole title. On your computer and in the phone app.
- The **Fast** chip offers **On** wherever the session's model takes fast mode, and dims it on a model without it, saying why. Where Claude Code turned fast mode off, as when your organization has, **On** says why, and choosing it tries again; after a rate limit, it says **Cooldown** until Claude Code turns fast mode back on. See [Session settings](https://moontors.com/docs/configuration/#session-settings).
- **Don't wait for me** says in one line under its name what it does, across the whole row, with its switch beside its name, and its ⓘ tells the rest: point at it on your computer, or tap it in the phone app. See [Don't wait for me](https://moontors.com/docs/permission-modes/#dont-wait-for-me).
- When you bring a session up, its composer takes the keyboard, so you can start writing at once: clicking its card with the panel open, a double-click or Enter on it, its card's **Open**, **Transcript** opening the panel, a notification or a link to it, reopening it from **Archived**, and a session you've just made or forked. See [The composer](https://moontors.com/docs/sessions-composer/).
- A command from Moontors' menus, by its keys or a click, first closes a menu or a dialog open in the window, as Escape would, then acts, so nothing it opens is left under what was open. See [Menus and your data](https://moontors.com/docs/menus-and-your-data/).
- A submenu opens beside the menu it comes from, its border at that menu's border, covering none of it, its first row level with its item.
- The **Archive** and **Delete** dialog opens with its question and what the session takes in place, and stays whole when it reads again what a session takes, on your computer and in the phone app. See [Archiving and deleting](https://moontors.com/docs/archiving-and-deleting/).
- On Windows without Git Bash, Claude Code runs its commands in PowerShell, and Moontors shows each as the command it runs.
- If a look for an update fails on the network, Moontors looks again a minute later, then twice as long after each one that fails, until the next 4-hourly look, and while your computer is offline it says nothing and looks again each minute. On Linux, a .deb update asks for your password to install; if you dismiss the prompt, the update stays ready and Try again asks again. See [Updates](https://moontors.com/docs/updates/).
- Where Moontors can't reach your system's keychain, as in a Windows session over ssh, the agents no longer all say they couldn't install: they sign in their own way and run, a sign-out there still takes effect once the keychain answers, and only saving an API key, a cloud sign-in or an MCP server's values says the keychain can't be reached.
- When git ends without an exit code, a worktree's failure or a Git action says why: Git couldn't start, was stopped before it finished, or didn't finish in time.
- The computer's **Phones** offers the phone app's Google Play page, and says the iPhone app is coming soon until it's on the App Store.
- On moontors.com, new comparisons with [Paseo](https://moontors.com/docs/compare/paseo/), [T3 Code](https://moontors.com/docs/compare/t3-code/) and [Herdr](https://moontors.com/docs/compare/herdr/), the [Orca](https://moontors.com/docs/compare/orca/) and [Emdash](https://moontors.com/docs/compare/emdash/) comparisons brought up to date, and [Keep agents running](https://moontors.com/docs/how-to/keep-agents-running-when-the-window-closes/) saying what each agent does in a terminal today.

This version updates the phone app on Google Play, and goes to Apple's review as its first iPhone version. The Windows and Linux builds still aren't signed, so Windows asks once before Moontors opens. The README's "First launch" and "Updates" sections say what to expect on each platform.
