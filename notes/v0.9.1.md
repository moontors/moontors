Moontors 0.9.1

Moontors, the agentic development environment (ADE) for Claude Code, Codex, Gemini CLI, Grok Build and OpenCode, now runs Claude Code 2.1.332, Codex 0.172.0, Gemini CLI 0.71.1 and OpenCode 2.4.2, beside Grok Build 1.0.92. This release lets you answer a message Claude Code holds from another session, and makes OpenCode's automations the session's timers.

What's new:

- **A message Claude Code holds from another session waits for your answer**, on your computer and your phone alike, where it used to expire. Claude Code holds one when the two sessions are in different permission modes. Its row shows the sender's words and offers **Deliver**, **Always deliver here**, **Always from my own sessions** and **Drop**; one your `crossSessionInbound` setting holds offers **Drop** alone. While it waits, its card says **Message held**, the header's waiting tag counts it, and you're notified as for any wait. Each Always you choose is listed in the session's configuration, where **Stop** ends it. See [Sessions messaging each other](https://moontors.com/docs/sessions-messaging/).
- **OpenCode's automations are its sessions' timers**: `/automation` sets one up, sending a prompt once at a set time, on an interval or on a cron, and the card says **Scheduled** with the next run. Each run shows in its session once it's over, as a turn the agent started itself. They outlive Moontors' background service stopping and `/restart`, as OpenCode keeps them; archiving the session pauses them, and deleting it, the agent's copy too, deletes them. See [What a typed command does](https://moontors.com/docs/conversation-commands/#what-a-typed-command-does).
- **Claude Code's `/slides` and `/whiteboard`**, where your claude.ai account has Artifacts, and **`/claude-approvals`**, where Anthropic turns it on for your account, are in the commands list, marked **Untested**: `/slides` and `/whiteboard` each make a new Slides deck or Whiteboard Artifact from a brief, `/whiteboard` in beta, and `/claude-approvals` edits, explains or tunes a Claude Approvals policy file or classifier.
- **Codex on Bedrock Runtime**: Codex's Amazon Bedrock sign-in asks which endpoint to run on, **Bedrock Mantle**, Codex's default, or **Bedrock Runtime**, which runs in any region where your account has Bedrock models, an ⓘ beside each saying which. See [Signing in](https://moontors.com/docs/sign-in/#ways-to-sign-in).

What's changed:

- **A Claude Code durable job runs only where it was made**: one made on a claude.ai organization's account runs only on that organization's accounts, and one made on an API key, Amazon Bedrock or Google Vertex AI on any of those, but not on an organization's account. Elsewhere Claude Code skips it and warns you in its own words, and the card doesn't count it as **Scheduled**. Switching the session's account keeps the job, so switching back runs it again. See [What a typed command does](https://moontors.com/docs/conversation-commands/#what-a-typed-command-does).
- **An Action denied outlasts a restart**: quit Moontors, or restart the computer, and a denial you haven't decided on is marked **Action denied** again when Moontors opens, its row's choices still offered. One you've kept denied stays kept, and the transcript says you kept it denied. `/clear` ends the mark too. See [Which agent has which](https://moontors.com/docs/permission-modes/#which-agent-has-which).
- With Claude Code, a message another session sends reaches the agent marked as relayed, so Claude Code never takes it as your own words.
- With Codex's **Daybreak** on, switching to a model that doesn't take it says why, where Codex does: your account not yet enrolled in Daybreak, or the model not offering it.
- When Anthropic holds your account or its organization until it's verified, the turn ends saying Claude Code needs your account verified, with Anthropic's own message and its link, in place of "The agent failed."
- Codex's spend limits on an API key, a project or an organization, and OpenCode's limits on a ChatGPT plan or workspace, end a turn as a usage limit.

What's fixed:

- With Gemini CLI, the short runs Moontors makes apart from a session, to rephrase a message, title a session or list its models before a session starts, follow your own usage statistics and telemetry settings, as its sessions do.
- A card's **Action denied** that opens a session for the first time since Moontors opened, as after a restart, goes to the denied call's row and marks it, where it could open the session without finding the row.
- A phone you remove in your computer's **Phones** while it isn't connected, as the last phone paired there, still can't learn it was removed, but its card now says what to do: forget the computer on the phone and pair again. Through the relay, it no longer says the same network or tailnet still reaches the computer. See [Limits](https://moontors.com/docs/phone/#limits).

This version updates the Android app and the iPhone app. The Windows and Linux builds still aren't signed, so Windows asks once before Moontors opens. The README's "First launch" and "Updates" sections say what to expect on each platform.
