Moontors 0.7.0

Moontors, the agentic development environment (ADE) for Claude Code, Codex and Gemini CLI, now shows each session's repository in a Git view: its branches and history as a graph, its working changes, and every Git action from a right-click, each asking first where it would lose work. You can paste an image or files into a message, and Moontors for Android now works in landscape and on tablets.

What's new:

- The Git view, in place of Diff: the session's repository at its folder or worktree, with its branches, remote branches, worktrees, stashes and tags, its history as a graph in lanes, and its working changes with a commit box. It follows the repository as it changes, so an agent's commit shows as it lands, and finds commits by message, author or SHA. The Git button at the window's right edge, or `/diff`, opens it. See [Git](https://moontors.com/docs/diff-and-files/#git).
- Every local Git action from its menu, with a right-click on a branch, a remote branch, a tag, a commit, the working changes, a stash, a worktree or a file: check out, merge, rebase, fast-forward, cherry-pick, revert, reset, branches, tags, stashes, patches and worktrees. An action that would lose work asks first and says what it loses: the commits no other branch or tag holds, and the files with changes. See [Menus](https://moontors.com/docs/diff-and-files/#menus).
- Fetch, pull and push from the button beside the find box. A force push replaces the remote branch only while it's still at the commit the view showed, so a teammate's push in the meantime is refused, not lost. Git uses the sign-ins already set up on your computer and never asks for a password here. See [Fetch, pull and push](https://moontors.com/docs/diff-and-files/#fetch-pull-and-push).
- A file's changes over the graph: git's own hunks, inline or side by side, the whole file, its blame and its history across renames. Stage, unstage or discard a file or a single hunk, revert a commit's hunk into the working changes, or restore a file from a commit. See [A file's changes](https://moontors.com/docs/diff-and-files/#a-files-changes).
- Each worktree names the sessions working in it: open one, or start a new session in that worktree. See [Worktrees and sessions](https://moontors.com/docs/diff-and-files/#worktrees-and-sessions).
- Each action is your own git, so your hooks and commit signing run too, and one that would change the files of a folder where an agent's turn is running asks first. A merge or rebase that stops at a conflict is finished in the session's terminal. See [How actions run](https://moontors.com/docs/diff-and-files/#how-actions-run).
- Moontors now needs git 2.23 or newer, for the Git view and for worktree sessions. See [Known limits](https://moontors.com/docs/known-limits/#platforms).
- Paste into the message box with Cmd+V (Ctrl+V on Windows and Linux): an image on the clipboard, such as a screenshot, attaches as `Pasted image 1.png`, and files copied in Finder or Explorer attach under their own names. Text still pastes as text. See [Adding files](https://moontors.com/docs/sessions-attachments/#adding-files).
- On Windows, terminals and agents get the environment Windows gives a new terminal: the machine's variables and yours, as System Properties sets them, so variables such as `JAVA_HOME` or `GOPATH` reach them. It's read again for each new terminal. A terminal's Windows PowerShell also keeps its own modules when Moontors was started from PowerShell 7, so its first command no longer stalls. See [The shell](https://moontors.com/docs/terminal/#the-shell).
- Moontors for Android turns with the phone and works in landscape, and on tablets and foldables shows the board, a session and its sheets in one centered column. See [Landscape and tablets](https://moontors.com/docs/phone/#landscape-and-tablets).
- Moontors for Android decodes attachment previews at the size they show, not at the photo's full size.
- Every Android release is checked before it goes to Google Play: nothing in it reports to Google, and it doesn't ask for the advertising ID. See [What the phone keeps](https://moontors.com/docs/phone/#what-the-phone-keeps).

The macOS and Windows builds still aren't signed, so each asks once before it opens, and macOS updates through its download page for now. The README's "First launch" and "Updates" sections say what to expect on each platform.

Found a problem, or have an idea? Open an issue: https://github.com/moontors/moontors/issues/new/choose
