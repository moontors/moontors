Moontors 0.2.0

Moontors, the agentic development environment (ADE) for Claude Code, Codex and Gemini CLI, now has its own website at https://moontors.com, with the docs, a reference for every slash command, and these release notes.

What's new:

- The agents are updated to Claude Code 2.1.295, Codex 0.162.0 and Gemini CLI 0.63.0.
- Codex's new /daybreak is offered on the accounts that have it. We couldn't test it on our own accounts, so it's marked Untested.
- A new Gemini CLI conversation can be reopened right away. Before, its first minute had to pass to work around a Gemini bug, which 0.63 fixes.
- Claude's sign-in can finish without a browser on the same machine: open the address on any device, and paste back the code it shows. That helps on a remote or headless Linux machine.
- Unsaved work is kept: closing the window or quitting first asks about unsaved file edits and composer drafts, with Save all, Discard or Cancel. On macOS a logout asks too, and on Windows a sign-out or restart waits while anything is unsaved.
- Help → Remove Moontors' Data… signs out of every agent, removes what Moontors keeps on the computer, and says what stays.
- Deleting a session now writes over its text in Moontors' database. On its first start, 0.2.0 keeps a backup of the database, then clears out what earlier deletes left behind.
- Deleting a Gemini CLI session now deletes Gemini's own copy too (its project's prompt log stays, as Gemini keeps it), and signing out of Gemini removes its record of the Google account.
- Paths are shown from ~, permission requests are titled by the kind of tool asking, and a setting that waits for a busy agent says so.
- A message sent while the background service restarts is never sent twice.

The macOS and Windows builds still aren't signed, so each asks once before it opens, and macOS updates through its download page for now. The README's "First launch" and "Updates" sections say what to expect on each platform, and [Known limits](https://moontors.com/docs/known-limits/) says when Windows' Smart App Control blocks an unsigned app outright.

Found a problem, or have an idea? Open an issue: https://github.com/moontors/moontors/issues/new/choose
