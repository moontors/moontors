Moontors 0.8.13

Moontors, the agentic development environment (ADE) for Claude Code, Codex, Gemini CLI, Grok Build and OpenCode, now runs Claude Code 2.1.330, Codex 0.171.0, Gemini CLI 0.70.0, Grok Build 1.0.92 and OpenCode 2.3.2. This release adds Quick feedback, a bug report or a feature request sent from the window, and gives Grok Build every mode.

What's new:

- **Quick feedback**: at the right end of the bar across the window's top, and first in the Help menu. Choose **Bug report** or **Feature request**, write what went wrong or what you'd like, and add screenshots and files as the composer takes them: paste them, drop them on the dialog, or choose **Add files**, up to 19 MB. A bug report carries Moontors' logs by itself. Closing the dialog keeps the report until you send or discard it, so you can take another screenshot and come back to it. You don't need a Moontors account, and an email for a reply is optional. See [Quick feedback](https://moontors.com/docs/quick-feedback/).
- **Grok Build's Plan and Edit automatically**, so Grok Build has every mode. In Plan it edits nothing but its plan, which it shows as a plan to approve, send back with your feedback, or approve into another mode, and it goes into Plan by itself when its model decides a task needs a plan first. In Edit automatically, Moontors allows each edit Grok Build asks about in the session's folders. See [Permission modes](https://moontors.com/docs/permission-modes/).

What's changed:

- Claude Code 2.1.330, Codex 0.171.0, Gemini CLI 0.70.0 and Grok Build 1.0.92:
  - With Codex, Manual and Auto take your own `sandbox_workspace_write` settings, such as `network_access` and `writable_roots`, from your `config.toml`, a trusted folder's, and your organization's managed config over both.
  - With Gemini CLI, a shell command that holds a variable, a `$(…)`, a wildcard or braces asks, even one Gemini CLI knows only reads.
  - With OpenCode, leaving Plan goes back to your default agent, Build unless your OpenCode config names another.
- **A switch to an account whose sign-in has gone** asks you to sign in to it first, and switches only once you have; cancelling leaves the account in use as it is. Where the agent's own read can't tell, as with a Claude Code claude.ai sign-in signed out elsewhere or a Grok Build API key, Moontors asks the vendor too, with no prompt sent, and it reads a cloud sign-in's end from what your computer keeps. A session the vendor refuses marks its account **Sign in again** until you sign in to it. See [Several accounts](https://moontors.com/docs/sign-in/#several-accounts).
- **Switch account**, with no other account to pick, opens the sign-in to add one at once, and once you've signed in to another account, Moontors switches to it.
- A session's MCP servers, opened where its agent isn't running, start it with nothing sent, so the list shows Claude Code's claude.ai connectors and Codex's apps beside the servers its files list. Claude Code loads claude.ai's connectors itself each time it starts.
- Codex's memories are each account's own, but the accounts signed in with an API key share one, and a sign-in again to an account keeps them.

What's fixed:

- On a saved Codex account, Codex makes its memories again; since 0.8.12 it made none there.
- On a saved Claude Code account, Claude Code no longer asks before writing its own plan in Plan, or its own memory.
- With Claude Code, a failed Stop hook no longer shows a second time as a plain row.
- A Gemini CLI session or sign-in no longer waits forever while Gemini CLI's own sandbox is turned on: it says which setting turns it on, so you can turn it off ([gemini-cli#30398](https://github.com/google-gemini/gemini-cli/issues/30398)).

This version updates the Android app; the iPhone app isn't updated this time. The Windows and Linux builds still aren't signed, so Windows asks once before Moontors opens. The README's "First launch" and "Updates" sections say what to expect on each platform.

Found a problem, or have an idea? Send it from **Quick feedback**, or open an issue: https://github.com/moontors/moontors/issues/new/choose
