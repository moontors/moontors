Moontors 0.8.7

Moontors, the agentic development environment (ADE) for Claude Code, Codex, Gemini CLI, Grok Build and OpenCode, now runs Claude Code 2.1.325, Codex 0.169.0, Gemini CLI 0.68.0, Grok Build 1.0.77 and OpenCode 2.3.0. This release brings OpenCode as a fifth agent; free AI from the first launch, in a welcome session that needs no sign-in; a model menu that marks what each model does, and a warning for a file the model can't read; Claude Code's suggested next prompt; and Codex's plan handoff to a new conversation.

What's new:

- **OpenCode**, Anomaly's open-source coding agent, runs in Moontors beside Claude Code, Codex, Gemini CLI and Grok Build. With no sign-in it runs on OpenCode's own free models, and shows as **Free models**: each is free for a limited time, with a daily limit of requests all your OpenCode sessions share, and while a model is free its maker may use what you send to improve it. Sign in with your OpenCode Console account by a device code for the Console's models, or paste an OpenCode Console API key for OpenCode Go's models beside them. Its models show by their own names, such as Big Pickle. It has Manual, Edit automatically, Plan and Bypass, and its rewinds restore files too, in a Git repository. See [OpenCode](https://moontors.com/docs/sign-in/#opencode).
- **A welcome session**: the first time Moontors opens on a computer, it opens on an OpenCode session on its free models, titled "Welcome to Moontors: I'm a free session, try me", its composer ready for your first message, so there's free AI from the first launch with no sign-in. Under its notice are three prompts to try, on your computer and your phone: **Make a web page**, **Find an idea** and **What can you do?**, each sent as your first message. It comes once, and an update never brings it. See [OpenCode](https://moontors.com/docs/sign-in/#opencode).
- **The model menu** marks what each model does at its row's end, each by an icon: that it reasons, what it reads beyond text (images, PDFs, audio and video), that it calls tools, that it reads and writes text, and what it makes beyond text. Point at one for its name, such as "Reads images". A model shows only what its agent says of it, and Gemini CLI says none. The menu shows six and a half of its rows and scrolls for the rest, opening on the model in use, and so does the output style's, under **More settings** (⋯) too. See [The model picker](https://moontors.com/docs/sessions-models/#the-model-picker).
- **A file the model can't read** is warned of before you send it, where its agent says what each model reads, as Codex and OpenCode do: its chip is outlined, and a line under the message names the model and what it can't read, as "Big Pickle can't read images, so it won't see shot.png." **Send** still goes, and a switch to a model that reads it takes the warning away. See [Attaching files](https://moontors.com/docs/sessions-attachments/#adding-files).
- **A suggested next prompt**: once a turn ends, Claude Code can suggest what you might send next, shown dimmed in the empty message box. Tab puts it in, to send as it is or change first; on the phone, the speech-bubble button does. Each suggestion is one more request to the model, on your plan or your key, so **Suggest my next prompt**, in Settings › **Composer**, turns them off. See [A suggested next prompt](https://moontors.com/docs/sessions-composer/#a-suggested-next-prompt).
- **In a new conversation**, under a Codex plan's Yes buttons, has the Yes you choose go on in a new conversation, as Codex's own terminal offers: the session clears, as `/clear` does, and Codex starts over with just the plan, the conversation before staying in the transcript. See [Plans](https://moontors.com/docs/questions-and-plans/#plans).
- **`/btw`** with Codex is answered on the conversation itself while Codex works too, from what it has done so far. See [The built-in commands](https://moontors.com/docs/conversation-commands/#the-built-in-commands).
- **Give feedback**, beside the ways on offer where Codex's safety check stopped a turn, opens `/feedback`'s report with Safety check already chosen. See [When the agent's safety check stops a turn](https://moontors.com/docs/sessions-notes/#when-the-agents-safety-check-stops-a-turn).
- **Sounds** go to Codex too, such as an MP3 or WAV file, for a model that hears sound. None of the models Moontors has seen Codex list hears sound yet, so each warns of a sound file. See [What each agent takes](https://moontors.com/docs/sessions-attachments/#what-each-agent-takes).
- **Sign in with a device code** to a Codex model gateway, where the gateway's administrator has set it up for codes: you enter a code on the gateway's page, handy where this computer's browser can't reach the gateway's sign-in. See [When a sign-in is needed](https://moontors.com/docs/sign-in/#when-a-sign-in-is-needed).
- **ChatGPT's security reminder**, such as setting up a second step to how you sign in, shows on Codex's card on Profile, and on the phone, in ChatGPT's own words, with its button to the page on chatgpt.com. See [Providers](https://moontors.com/docs/sign-in/#providers).
- **Sandboxed commands ask** with Claude Code 2.1.325, as any other command does, so `/sandbox`'s **Allow sandboxed commands without asking** shows off until you turn it on. See [The agent's own lists](https://moontors.com/docs/configuration/#the-agents-own-lists).
- **Usage credits**: where a Claude Code model came with your plan or your team seat as a promotion that has ended, the card asking to go on with usage credits says until when. See [Choices](https://moontors.com/docs/questions-and-plans/#choices).
- **Background subagents** with OpenCode 2.3.0: the turn that starts one ends while it works, and each time it goes idle its report starts a turn of OpenCode's own. **Stop** stops them too, each row saying **Stopped**. See [Tools and subagents](https://moontors.com/docs/sessions-tools/).
- **OpenCode's limits**: once its free models reach their daily limit, the session stops and says so, with **Sign in to OpenCode** beside it to go on. OpenCode Go's limit, a Console workspace's budget and a provider's quota stop it as a usage limit does, in OpenCode's own words. While OpenCode waits out a limit to try again, a note says so, and when it tries next. See [Known limits](https://moontors.com/docs/known-limits/#sign-in-and-accounts) and [Quiet rows](https://moontors.com/docs/sessions-notes/#quiet-rows).
- **A background service crash** is fixed: watching a folder for changes, as Moontors does for Claude Code's forks and the Git view, could crash its background service and end every running turn, on macOS, Windows and Linux. Folders are now watched through Node's own watching on each.
- On moontors.com, the search loads only once you reach for it, so pages load faster, and a new article: [Claude Code hit its usage limit? How the limits work, and how to keep working](https://moontors.com/articles/claude-code-usage-limit/).

This version updates the phone app on Google Play. On the Android phone, OpenCode shows by its logo, with its free models and its rewinds that restore files, and the welcome session's prompts to try, the model menu's marks, the warning for a file the model can't read, Claude Code's suggested next prompt, Codex's **In a new conversation** and ChatGPT's security reminder come to it too; the iPhone app isn't updated in this version. The Windows and Linux builds still aren't signed, so Windows asks once before Moontors opens. The README's "First launch" and "Updates" sections say what to expect on each platform.
