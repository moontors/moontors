Moontors 0.8.10

Moontors, the agentic development environment (ADE) for Claude Code, Codex, Gemini CLI, Grok Build and OpenCode, still runs Claude Code 2.1.325, Codex 0.169.0, Gemini CLI 0.68.0, Grok Build 1.0.77 and OpenCode 2.3.0. This release moves a running command to the background, approves a denied call once, brings Grok Build's own Auto mode and checks an MCP server's connection before you add it, and a long session opens on its newest turns at once.

What's new:

- **Run in background**: while Claude Code runs a command or a subagent in the foreground, holding up its turn, its row offers **Run in background**, as Claude Code's own Ctrl+B does. The turn goes on, and the call keeps running in the background: a command as a background task with its **Output** and **Stop**. It's in Moontors' Android app too. Codex and Grok Build move a long command to the background themselves. See [Background tasks](https://moontors.com/docs/configuration/#background-tasks).
- **Approve once** for Claude Code and Grok Build: a call they denied, such as one their Auto mode's check blocked, can be approved once from its row, or from `/approve`. Moontors sends, as your message, that you approve that exact command once, in the words the agent takes as your consent, and the agent tries it again once the turn under way ends. **Approve once** now shows, as code beside it, exactly what it approves, with Codex too. See [Which agent has which](https://moontors.com/docs/permission-modes/#which-agent-has-which).
- **Auto for Grok Build**: Grok Build's own Auto mode joins Manual and Bypass. Its check lets routine work through without asking, and a call it blocks shows as **Denied** with its reason, ready for **Approve once**. See [Which agent has which](https://moontors.com/docs/permission-modes/#which-agent-has-which).
- **Check connection** for MCP servers: the Add MCP server form, and each server Moontors added, try the server as an agent would, by its URL with your headers or by running its command. It says whether the server connected and how many tools it offers, asks you to sign in, refused, can't be reached, didn't start or didn't answer, and why. **Add server** checks it too, unless you checked it and changed nothing it goes by, and the server's row shows its last check. What you typed in its headers and environment variables is never shown back. See [Checking the connection](https://moontors.com/docs/configuration/#checking-the-connection).

What's changed:

- A long session opens on its newest turns at once, the rest of its transcript loading behind them, while the agent's reply still comes in word by word. In our measurement of a session of 280,000 events, its newest turns showed in about a tenth of a second, where 0.8.9 drew the whole transcript first, in over two seconds.
- Each MCP server's row shows its name with its status and tag on one line, its actions as small words under it and its switch at the right, so a long name stays in sight. See [`/mcp`](https://moontors.com/docs/configuration/#mcp).
- What a transcript row offers, such as **Approve once**, **Keep denied**, **Run in background**, **Send now** and **Edit**, is small text that's underlined as you point at it, each reached with Tab and pressed with Enter. On the phone each keeps a finger's room. The welcome's starters and an error's **Sign in** stay buttons.
- While a newer Moontors waits to take over, the line under the header names each session it waits for and what it waits on, such as an MCP sign-in still open in your browser. See [Updates](https://moontors.com/docs/updates/).
- On Android, **Share usage numbers and error reports** has left the pairing screen. It's in **Accounts** once the phone is paired, and before that in the Accounts of **See a demo**, where it's your phone's own switch; the Privacy Policy says so. See [Usage numbers and error reports](https://moontors.com/docs/phone/#usage-numbers-and-error-reports).
- **Continue with Google**, **Continue with Apple** and **Continue with GitHub** on the Moontors account's sign-in pages each show their provider's mark. See [Signing in](https://moontors.com/docs/moontors-account/#signing-in).

What's fixed:

- An MCP server's switch could show on in a view left open after you'd turned it off elsewhere, so **Reconnect** was refused and Claude Code's **Sign in** said the server was off. Every view now shows the switch as it's stored, and catches up when it changes.
- With Claude Code, an MCP sign-in whose server refused the token Claude Code got, or one you refused in the browser, said **Finish in your browser** for 5 minutes, holding an update back meanwhile. It now ends a few seconds after the browser's done, saying the server still needs a sign-in. **Sign in** pressed again while one waits opens the same page, never a second sign-in. See [Known limits](https://moontors.com/docs/known-limits/#configuration).

This version updates the Android app; the iPhone app isn't updated this time. The Windows and Linux builds still aren't signed, so Windows asks once before Moontors opens. The README's "First launch" and "Updates" sections say what to expect on each platform.
